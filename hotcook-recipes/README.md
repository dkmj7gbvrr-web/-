# ホットクック野良レシピ帳（hotcook-recipes）

ネットで見つけたホットクックの「野良レシピ」（公式以外のブログ・レシピサイト・SNS のレシピ）を、
**URL を貼るだけで「料理名・材料・工程・使うモード」に整理して保存**できる Web アプリです。
Vite + React + TypeScript で、サーバー不要・ブラウザだけで動きます。

公開URL: https://dkmj7gbvrr-web.github.io/-/hotcook-recipes/

## できること

- **URLから取り込み**：レシピページを読み込み、料理名・材料・工程・ホットクックのモードを自動で取り出す
  - ページに埋め込まれたレシピ情報（schema.org の Recipe 形式）があればそれを使う
  - 無ければ「材料」「作り方」の見出しから推測する
- **画像（スクリーンショット）から取り込み**：レシピのスクショを選ぶと文字を読み取り（OCR）、料理名・材料・工程・モードに整理する。
  複数枚にまたがるレシピはまとめて選べば選んだ順につなげて読む。読み取りは端末内で行い、画像はどこにも送らない
  （「ふたりの家計簿」と同じ Tesseract.js 一式を `public/vendor/tesseract/` に置いている。初回だけ数MBを読み込む）。
  誤字が出やすいので、保存前の確認が前提
- **Claude Code のチャットから登録**：このリポジトリで開いた Claude Code のチャットにスクショを貼って共有コードを伝えると、
  Claude が読み取って共有レシピ帳に直接登録する（`tools/add-recipe.mjs`。手順は [`.claude/skills/hotcook-add-recipe/SKILL.md`](../.claude/skills/hotcook-add-recipe/SKILL.md)）
- **テキストから取り込み**：ページ全体のコピーや Instagram・YouTube の説明欄を貼り付けて読み取る（URL の取得に失敗したときの逃げ道）
- **モードの自動抽出**：「手動で作る→煮物を作る（まぜる）→30分」「メニュー番号123」「煮物2-1」などの書き方を拾い、
  `手動 › 煮物を作る（まぜる） 30分` / `自動メニュー No.123` の形にそろえる。拾った根拠の原文も表示する
- **一覧・検索**：料理名・材料・モードで検索、モード別（自動メニュー / 手動・煮物 / 手動・炒める…）とタグで絞り込み、
  登録順・最近作った順・よく作る順・評価順・名前順で並べ替え
- **詳細**：材料のチェックリスト、番号付きの工程、★評価、「作った！」の回数と最後に作った日、メモ
- **重複チェック**：同じ URL（utm パラメータや末尾の / の違いは無視）を登録しようとすると知らせる
- **共有メニューから追加**：ホーム画面に追加すると、Android では共有メニューにこのアプリが出る（Web Share Target）
- **みんなで共有**：共有コード（または招待リンク）を知っている人同士で、レシピの追加・編集・削除・「作った！」がリアルタイムに同期される。
  ログイン不要。「作った！」は同時に押しても数がずれないよう加算で記録する。共有をやめても、それまでのレシピは端末に残る
- **バックアップ**：JSON で書き出し／読み込み（別端末への引っ越しにも使える）
- ダークモード対応、新しい版を公開したら自動で読み込み直す（`version.json` 比較。入力中はバナーで知らせるだけ）

## しくみと制約

- **共有していないとき、データの保存先はこの端末のブラウザ（localStorage）だけ**です。サーバーには送りません。
  ブラウザのデータを消すと消えるので、設定画面から時々書き出してください。
- **共有しているときは Firebase Firestore に保存**します（`src/sync.ts`）。「ふたりの家計簿」（[`docs/`](../docs)）と同じ Firebase プロジェクトを使い、
  保存場所を `recipeBooks/{共有コード}/recipes/{レシピID}` に分けています。家計簿のデータ（`households/…`）とは混ざりません。
  - 共有コードを知っている人は誰でも読み書きできます（家計簿の世帯コードと同じ考え方）。信頼できる人にだけ送ってください。
  - Firebase の無料枠は家計簿と分け合います。
- **ページの取得には中継サーバー（CORS プロキシ）を使います。** ブラウザは他サイトのページを直接読めないためです。
  - 既定では無料の公開プロキシ（allorigins / codetabs / corsproxy.io）を順に試します。
    提供元の都合で止まったり、レシピサイトに拒否されたりすることがあります。
  - 安定させたい場合は [`worker/cors-proxy.js`](./worker/cors-proxy.js) を Cloudflare Workers に置き、
    そのURLをアプリの「設定 › 中継サーバーのURL」に入れてください（このアプリのページからの要求だけに応えるよう制限してあります）。
  - 取得したいページのURLが中継サーバーの運営者に見える点に注意してください（自分の Worker ならその心配はありません）。
- **モードの抽出は推測です。** 書き方によっては拾えない・違うものを拾うことがあるので、保存前の画面で直せるようにしています。
  メニュー番号は機種によって異なることがあります。

## 共有のための準備（最初に1回だけ）

共有機能を使うには、Firebase のセキュリティルールにレシピ帳の分を足す必要があります。

1. https://console.firebase.google.com/ を開き、家計簿で使っているプロジェクト（`lifev2-6bf0b`）を選ぶ
2. 左メニュー「構築」→「Firestore Database」→ 上部の「ルール」タブ
3. このリポジトリの [`docs/firestore.rules`](../docs/firestore.rules) の内容を**丸ごと**貼り付けて「公開」

> **注意:** このファイルには家計簿とレシピ帳の両方のルールが入っています。レシピ帳の部分だけを貼ると、家計簿が読み書きできなくなります。

ルールを公開する前に共有を始めようとすると、アプリに「Firebase のセキュリティルールが更新されていない可能性があります」と表示されます。

## 開発

```bash
npm ci
npm run dev      # 開発サーバー
npm run test     # 解析ロジックのテスト（vitest）
npm run build    # dist/ に出力
```

共有機能を手元で試すときは、Firestore エミュレーターを起動し、`VITE_FIRESTORE_EMULATOR=127.0.0.1:8080 npm run build` のように
エミュレーターの場所を渡してビルドします（指定しなければ本番の Firebase につながります）。

解析ロジックは `src/parse/`（`jsonld.ts`＝構造化データ、`text.ts`＝見出しからの推測、`mode.ts`＝モード抽出）に、
画面から独立した形でまとめてあり、`src/parse/parse.test.ts` で確認しています。
