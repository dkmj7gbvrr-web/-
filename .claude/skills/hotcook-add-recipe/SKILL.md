# 共有レシピ帳にレシピを登録する

ユーザーがチャットに貼ったレシピ（X のポストやレシピサイトのスクショ、コピーした文章、URL）を読み取り、
`hotcook-recipes/tools/add-recipe.mjs` で共有レシピ帳（Firestore `recipeBooks/{共有コード}/recipes`）に書き込む。
書き込んだレシピは、同じ共有コードで共有中のアプリにリアルタイムで表示される。

## 前提
- 書き込めるのは **共有中のレシピ帳だけ**。共有していない（端末内だけの）レシピ帳には書き込めない。
- **共有コード**（英小文字と数字12文字。アプリの「設定 › みんなで共有」に表示）が必要。チャットに無ければユーザーに聞く。
  共有コードを知っている人は誰でも読み書きできるので、リポジトリのファイルやコミットメッセージには書かない。
- 依存パッケージ: `cd hotcook-recipes && npm ci`（`firebase` を使う）。
- 書き込み先は `firestore.googleapis.com`。スクリプトがここに接続できない（ネットワークエラーになる）ときは、
  チャットの環境のネットワーク設定でこのドメインが許可されていない可能性がある。推測で別の方法を試さず、
  環境メニュー →「Edit」→ ネットワークアクセスで `firestore.googleapis.com` を許可するようユーザーに伝える。
- アプリの「Claude で登録」ボタンからコピーされた依頼文には、共有コードとこの手順書の場所が書かれている。
  チャットにこのリポジトリが無ければ、まずリポジトリを追加・取得してからこの手順に従う。
- **ユーザーの機種は KN-HW16H（1.6L）**。容量によって時間やメニューが違うと書かれている場合は、
  1.6L の分だけを工程・モードに書き、他の容量（1.0L・2.4L など）の分は入れない。
  1.6L の分が書かれていないときは、推測せずユーザーに確認する。

## 手順
1. **読み取る**：画像・文章から、料理名・分量・材料・工程・ホットクックの設定・補足を拾う。
   - 読めない／途中で切れている箇所を推測で埋めない。不明な点はユーザーに確認するか、メモに「不明」と書く。
   - 複数枚のスクショは重複部分（スクロールで重なった行）を1つにまとめる。
   - URL を渡されたときは取得を試す。この環境のネットワーク設定で多くのサイトは拒否されるので、
     取れなければその旨を伝え、スクショか本文のコピーを貼ってもらう。記憶や推測で中身を作らない。
2. **JSON にする**（一時ファイルは scratchpad に置く）。形はスクリプト冒頭のコメントのとおり。
   - `ingredients`：1行1材料。グループ見出しは「【ソース】」のように1行で入れる（アプリが見出しとして表示する）。
     「大4」「小1」は「大さじ4」「小さじ1」のように読みやすくしてよいが、分量の数字は変えない。
   - `steps`：1行1手順。「↓」などの区切り記号は入れない。
   - `modes`：ホットクックの設定。表示名 `label` はアプリ（`src/parse/mode.ts` の `modeLabel`）の形にそろえる。
     - 自動メニュー: `kind: "auto"`, `menuNo: "42"` → `label`「自動メニュー No.42」。メニュー名・時間が書かれていれば後ろに足す（例「自動メニュー No.42 さばのみそ煮 20分」）
     - 手動: `kind: "manual"`, `category`（例「煮物を作る」）, `stir`（「まぜる」/「まぜない」）, `minutes`, `celsius` → `label`「手動 › 煮物を作る（まぜる） 30分」
     - どちらとも言えないもの: `kind: "other"`
   - `source`：出典（サイト名、X ならアカウント名）。`url` があれば入れる（重複判定に使う）。
   - `memo`：本文中の補足（容量違いの時間は上のとおり 1.6L の分だけ使い、メモにも他の容量の分は書かない）。
3. **確認してから書く**：まず `--dry-run` で内容と重複チェックを確認する。
   ```bash
   node hotcook-recipes/tools/add-recipe.mjs <共有コード> <recipe.json> --dry-run
   node hotcook-recipes/tools/add-recipe.mjs <共有コード> <recipe.json>
   ```
   - 同じ URL（URL が無ければ同じ料理名・出典）が登録済みなら書き込まずに終了コード 2 で止まる。追加してよいとユーザーが言ったときだけ `--force`。
   - 登録済みのレシピを直すときは、直した JSON を作って `--update=<レシピID>` を付けて実行する
     （評価・作った回数・登録日は残る）。レシピIDは登録時の出力に出る。
4. **報告する**：登録した内容（料理名・材料・工程・モード）と、読み取りで迷った点・推測した点を分けて伝える。
   スクリプトは書き込み後に読み戻して確認しているので、その結果（材料◯行／工程◯行）も添える。
